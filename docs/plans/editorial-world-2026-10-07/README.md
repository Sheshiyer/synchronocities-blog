# FIELDWORK — a spatial planning world

The editorial and product portfolio becomes a place to explore. Thoughtseed is a workshop archipelago; Tryambakam Noesis is an observatory and manuscript garden. A source field connects work to its evidence. Platform drafts gather at publishing docks. The seven-day expedition trail records intended work while each public item retains its exact human approval gate.

This October 7 prototype is a private local projection of the verified portfolio census and today's exact social packet. Its full data includes private repository metadata, so it must remain loopback-only. It is deliberately outside the blog's deployable assets. An authored miniature world, readable journal and day trail replace the dashboard table/KPI framing.

## Experience rules

Navigation should feel like moving across a game map: orbit, zoom, select a landmark, read a journal, then choose the next expedition. Objects have distinct silhouettes and roles. Brand color is useful orientation: amber workshop, jade observatory. Connection mode reveals edges without replacing the world with a dashboard. Search and keyboard interaction offer a direct route when the map is crowded.

Planning writes a versioned local browser proposal only. It cannot grant approval, alter the installed publication queue, post, upload, schedule remotely, mutate GitHub, change hosting or deploy. The daily automation still prepares at10 Paris. An approved public item needs a separate exact authorization and visible delivery readback. No points, completion streaks or auto-generated approval reward is introduced.

Reduced motion suppresses ambient effects and camera tweening. Pause offers manual stillness. Native media controls retain deliberate playback. A text directory remains usable if WebGL is unavailable. Small screens use the same journal and day choices without requiring precise raycast targets.

## Implementation and integration sequence

1. **Private playable projection, this pass.** Use the locally installed Three.js, verified October7 data, local media allowlist and browser-only proposed plan storage. Demonstrate selection, exact-copy review and persistence. No connector writes.
2. **Visual iteration.** Review the miniature world, navigation and density; decide whether to deepen exploration with a walkable avatar, route-following or a quest book. These are optional refinements, not current implemented claims.
3. **Persistent planning contract.** Connect exported proposals to the ISA/calendar through a narrow reviewed import. Define work/item IDs, relationship provenance, source freshness, conflict/replay semantics and the distinction between plan, approval and delivered receipt. LocalStorage remains a prototype convenience until that contract is accepted.
4. **Read-only refresh.** Reuse the source census/domain reads incrementally; keep public-safe and owner-only views separate. Render observation dates and stale/error states. Map native Substack draft/Note receipts into the world only after exact reconciliation.
5. **Human review station.** A future approval action binds body/title, audience, destination, media hashes, source claims and time. It must invalidate on change and cannot be auto-clicked by an agent or earned through game progression. This prototype does not implement that authority.
6. **Delivery and return.** After exact human approval, existing supported platform operations submit once and return an external ID/readback. The world consumes that receipt and records reader feedback without rewriting prior observations.

The first deliverable is an inspectable design and local interaction model. Live synchronization, multi-device state, public-safe hosting and actual platform approval/delivery remain separate implementation gates.
