I’m building Selemene as part of Tryambakam Noesis. A recent change in its public Gene Keys code separates short labels from the fuller meanings that are unavailable in the supplied material. Those description fields remain empty, and the code identifies Selemene’s reflection questions as its own writing.

That leaves a practical interface question. If a label is present but the explanation behind it is missing, what does a reader need to see before using it? A heading can look complete on a screen even when it gives very little context.

For a reader-facing version, I would put the source link beside the available label and explain what is absent at the point where someone expects to read more. An original reflection question could occupy its own section, with its authorship stated. This is a proposed screen treatment. The public evidence here is the source change.

The distinction matters to interpretation. Someone may choose to work with a short label, look for the author’s explanation, or leave the reading unfinished. The tool needs to make the available material clear enough for that choice.

When you use a symbolic reference, how would you want it to show that part of the source is unavailable?
