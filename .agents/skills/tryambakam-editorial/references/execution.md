# Scoped calendar execution

## Low-maintenance workflow

Preparation continues when a channel is unavailable: read, adapt and queue drafts independently of transport readiness. Use working CLIs for bounded research and verified supported publication; use Codex IAB when a CLI fails before claim. Substack normally uses IAB. Instagram/Reddit browser login alone does not establish a tested publishing workflow.

All transports share the approval ledger, hashes, cadence and receipts. Choose transport before claim. After a claim or possible submission, never switch and resubmit automatically: reconcile against the actual platform first. Refresh visible account identity before each write. Browser identity and CLI identity are independent.

Keep browser credentials in the browser. Do not create a copied-cookie .env store as a routine fallback. Existing protected CLI credentials may enter the child process environment in memory. A future supported cookie adapter must verify exact account identity before enabling writes; credential extraction must not become a dependency of preparation.

Cap scheduled maintenance investigation at 15 minutes per run. Record the failing capability and defer deeper repair to a reviewable task. Suppress unchanged known failures; notify once for newly actionable session expiry. Upgrade for a concrete capability need or meaningful benefit, retaining tested versions and rollback receipts.

`python3 scripts/calendar_runner.py` is a stdlib CLI. Run from this skill directory. The private state defaults to `~/.codex/editorial/tryambakam`; it must remain outside Git. Files use mode 600, directories mode 700. No command grants approval.

- `plan --date 2026-10-01 --blog-root /absolute/current/blog` reads the actual 26-week baseline table. It selects the next article week (including its Saturday Note), emits source paths/hashes and Paris offsets, and labels X slots as additional proposals. First article October 8, Notes October 6/10. The October 3 reintroduction is a separate prose proposal. Missing manuscript/vault sources remain held. These are preparation tasks, not completed adaptations.
- `discover --fixture /absolute/list.json` exercises a separate fixture namespace. Input is a list of Bird-shaped `{id,text,author,createdAt}` entries, at most 100 and 2 MB. `discover --live` uses at most seven topic queries, three results each. It performs public discovery, not an authenticated account listener. All seven Aleph families are mapped in `watchlist.json`; there are no enabled author handles or invented identities. Results are research candidates with context gaps, never generated comments or approvals. Stable `x:ID` packets are durable before dedup state advances; atomic replay overwrites the deterministic packet safely. Polls back off 30 minutes, or one hour on failure. Dedup capacity is 10,000 IDs and requires reviewed archival at that point.
- `doctor` reports command presence, which does not establish authentication or publishing. `doctor --live` explicitly probes Bird identity. Existing X credential failure remains unresolved. Reddit and Instagram are not submission adapters.
- `enqueue-draft --packet /absolute/complete-draft.json` accepts the existing queue payload schema with `status=draft`, `id`, explicit timezone `not_before`, account, destination, audience, email choice, body, sources and optional media. Exact file hashes must match. Approval fields are forbidden; existing approved/publishing/published/reconciliation rows cannot be overwritten. Research packets are incomplete and cannot be enqueued directly.
- `publish ID` or `publish ID --dry-run` checks approval/source/cadence without claiming or sending. `publish ID --submit` is only for an exact human-approved short X text post/reply. Fresh Bird `whoami` must match the approved handle, replies require exact target readback, queue.py performs its existing claim/digest/duplicate gates, and author ID, handle, exact body and reply target must match subsequent readback. Claims are followed by a second payload/source/authorization check. Nonzero, timeout, ambiguous create or readback mismatch becomes `reconcile`, with no automatic retry. Evidence stores only sanitized verification metadata, not raw auth output.

Installed executable embedded JavaScript confirms normalized read records contain `author:{username,name}`, top-level `authorId`, and `inReplyToStatusId`; synthetic readback fixtures use this actual shape. A revoked publishing claim is held without sending or rewriting the operator status. Durable packet replay advances dedup state without repeating its created notification.

Current installed Bird plain identity labels (`user:` and `user_id:`) were verified against executable command source. Tokens are supplied only through the subprocess environment: existing AUTH_TOKEN/CT0 first, then literal auth_token/ct0 config fields. No shell sourcing, token arguments, credential printing or credential persistence. All subprocesses have a 25-second wall timeout and bounded returned stdout; errors are generic. Synthetic tests substitute both environment loading and subprocess transport.

X Articles, media, Instagram and Reddit publication are explicitly held before claim. Substack gives an IAB handoff before claim: refresh authenticated Published/Drafts, verify account and overlap, check target/audience/email and preview the exact approved item. No Substack editor action is implemented by this script. The prior acceptance receipt records nine published posts and two drafts; refresh that state before editor work.

Cadence is conservative: at most two published items per Paris day (therefore at most two per invocation), one X reply per Paris day, one article/essay per platform in seven days. This is enforced using existing published ledger timestamps. An outstanding publishing/reconcile row holds further queue claims. Failed identity before claim leaves approval unchanged.
