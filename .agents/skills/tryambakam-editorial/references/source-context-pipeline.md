# Executable source and asset context

`calendar_runner.py refresh-inventory` reads the existing archive catalogue, concept registry and corpus census, then refreshes current blog paths, bytes and hashes. Those registries retain their identities and provenance. Concept outlines, source holds and private/runtime prepared-copy census rows appear as held metadata; their bodies are not projected. The projection also reconciles the existing 23 Noesis and 80 Thoughtseed workObject identities, preserving workId, promotion/admission/tenant fields, sourceRefs, registry date and sourceInventory metadata. These remain restricted metadata until deliberately classified evidence is selected. The Cloudflare asset projection preserves bucket access limits and current observations; bucket existence does not admit an object. The projection is a view over existing records, not a second authorial canon. An indexed public source is available for investigation, not certified science or permission to republish.

`prepare-day` selects one complete eligible blog source, with unused sources ahead of previously assigned sources and newest local source dates first. Brands alternate deterministically from October 9, 2026: Tryambakam Noesis, then Thoughtseed. The Why Chromosome is a channel destination within the Noesis lane, not a substitute portfolio brand. Thoughtseed days require explicitly classified current Thoughtseed public-project evidence; otherwise a source-selection hold is produced without relabelling a Noesis article. The explicit `--source-id blog:slug` option chooses a different eligible lead. It never picks a concept in place of a missing manuscript. Nine Muse responsibilities are projected from the existing registry; a missing or stale report is explicit. Registry profiles are role definitions, not fresh report availability. A named local reviewer can deliberately cover unavailable reports with a scoped disposition rather than pretending all nine reports exist. Registry availability does not claim a Muse has read or produced a report.

Preparation carries the full bounded source text, exact UTF-8 byte and line locators, passage hashes, current canonical writer guidance, current contract, source/asset identities, provenance, access classification and observation time. No authored copy, semantic-review claim or approval is fabricated. Project evidence is optional and explicit: a JSON array of deliberately public-eligible records `{id,path,sha256,access,observedAt,provenance}` under the blog's editorial evidence paths. If the story needs a project availability or capability claim, supply its current evidence; an empty evidence array cannot support that claim. Keep private/client sources out of this handoff. A Thoughtseed lead additionally requires `brand:"thoughtseed"` and `source_kind:"public-project-evidence"`, plus a title; an existing registry identity alone is insufficient.

An optional reviewed asset manifest contains `assets[]` with `{id,path,sha256,access:"publication-eligible",observedAt,provenance,reviewed:true,reviewer,role,alt}`. Existing asset hashes alone are insufficient: an asset without explicit review/classification is excluded and creates an unresolved finding. Accepted assets remain in `public/` or `docs/editorial/`; paths, bytes, labels and source-manifest provenance are retained. No asset is generated, visually certified or approved by this command. A reviewer must actually inspect it.

Changed source, package, evidence or asset input holds instead of overwriting the prepared day. Use a deliberately new assignment date or retain/review the existing artifact; never erase review history to make replay pass. The historical `plan` command still exposes its 26-week baseline and is not the new daily default.

## Complete adaptation gate

A human or explicitly assigned writer prepares the body and native channel adaptation, reads the actual sources and current integrated writer package, and performs a complete semantic review. Resolved preparation findings may then be cleared with evidence; a script must not clear them merely to make enqueue pass. Attach `context_bundle`, `asset_manifest` and `writer_review` to the existing queue payload. The review must bind writer v2.20.0, contract `noesis-writer-human-direction-2026-10-09-v4`, current package/contract/context/asset/payload digests, actual reviewer, `source_coverage:true`, `semantic_review:true`, `verdict:"ready-for-human-review"`, and `unresolved_findings:[]`. These attestations bind a review and expose drift; they cannot prove anyone read or certify prose quality.

Package SHA256 hashes a compact UTF-8 recursively sorted JSON mapping of every relative regular package file path to its SHA256, excluding `.git`, `__pycache__`, and `.DS_Store`. Symlink package files are rejected. Context and asset digests hash their entire structured objects with the same canonical encoding: `sort_keys=True`, `ensure_ascii=False`, `separators=(',', ':')`, no NaN.

Queue payload SHA256 uses exactly these keys, missing fields mapped to null: `platform,kind,account,destination,target_url,audience,send_email,body,media,sources`. The Field Report `review_sha256`/approval fingerprint separately covers its complete displayed review draft and is **not** the queue digest. A changed title or context can invalidate Site approval even if the narrow queue digest does not change. Keep those identities distinct.

No timeline mode is imposed during preparation. The writer chooses genre, relevant meaning axes, and how historical material enters this particular work. No scale, exposure pattern, scene, triad or conclusion is compulsory.

## Retrieval boundary

Use these verified direct-file commands as the executable fallback. Do not invoke a missing `scaffold`/article-generator command. Do not depend on a Meru service, semantic index or vault connector merely because a historical instruction mentions one: verify the capability and freshness independently before adding it to an assignment. Search can locate a file; only its read bytes and source locator establish coverage. Do not substitute a search snippet or generated summary for the source.

For unavailable Muse roles/reports, record `muse_coverage.disposition = {reviewed:true, reviewer:"actual local reviewer", reason:"specific coverage and limits", missing:["exact missing ids"], mode:"local-source-review", reviewer_kind:"agent"}`. Use reviewer_kind:"agent" or "human" truthfully. Keep actual missing IDs unchanged; never mark a report available because a local reviewer covers its question. Local review is not human publication approval. A structurally valid held Site candidate may retain findings, while ready/enqueue remains strict.

The projection links the existing dated October9 GitHub census by original private locator, hash, observation date and coverage summary (331 repositories, 222 public/109 private/15 forks). Existing repository/workObject links are metadata only; the command makes no new API request and reads no repository bodies.

### Reviewed original evidence

External vault/resource or project text requires an entry in the trusted local `docs/editorial/integrated-pipeline-2026-10-09/evidence-authorizations.json` ledger. Each entry pins a configured root ID, exact original path and SHA256, selected UTF8 byte range, publication-eligible context classification, reviewer identity/kind, and authorization scope. A caller label alone cannot admit it. Original files are bounded to 8 MB and selected passages to 192 KB; original SHA and byte/line locators survive projection. Private/client bodies remain excluded. An authorization permits the selected passage as review context; it does not authorize wholesale source republication or prove source claims. Current fixed roots are the requested vault 03-Resources and the public Synchronocities project. New project roots require deliberate code/config review.
